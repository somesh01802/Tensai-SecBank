# Kibana dashboards

All objects are generated by `build-dashboards.mjs` (`node kibana/build-dashboards.mjs`) and read only the
existing data: `tensai-transactions`, `tensai-users`, `tensai-accounts`, `tensai-login-events`
(written by `api/bin/export-to-elastic.php`) and `traces-apm*` (Elastic APM PHP agent + browser RUM).

| File | Contents | When to import |
|---|---|---|
| `tensai-panels-update.ndjson` | data views, every panel/saved search, and the **new** "Journeys, Failures & Satisfaction" dashboard | Updating an existing install — never overwrites the Business / APM dashboards you have customised |
| `tensai-dashboards.ndjson` | everything, including the Business Overview and Real-time APM dashboards | First install only |

Import: **Stack Management → Saved Objects → Import → "Check for existing objects" → overwrite**.

## Fields added by the 0007 upgrade (additive — no existing field changed)

`tensai-transactions` — one doc per ledger transaction (as before) **plus one per failed attempt**
(`record_type: "failed_attempt"`, `status: "FAILED"`, `_id` = attempt id). New fields: `record_type`, `attempt_id`,
`kind`, `outcome`, `error_category`, `failure_reason`, `duration_ms`, `http_status`, `trace_id`, `session_id`, `target`,
`fault_injected`, `attempt_at`, `is_synthetic`, `user_ref`, `feedback_status`, `feedback_rating`, `feedback_at`.
Panels that mean "completed ledger transactions" must filter **`not record_type : "failed_attempt"`** (the bundled
panels already do; add it to any panel or Canvas element you built that counts all docs).

`tensai-login-events` — `session_id`, `user_ref`, `is_synthetic`, `location_status`
(`granted | denied | dismissed | unavailable | timeout | error | unknown`), `geo_location` (`geo_point`, rounded to
2 decimals ≈ 1.1 km, present only when the user granted permission), `location_accuracy_m`.

`tensai-users` / `tensai-accounts` — `is_synthetic`; users also `role`, `user_ref`.

`traces-apm*` labels — `session_id`, `user_ref`, `synthetic`, `attempt_id`, `txn_kind`, `txn_outcome`,
`error_category`, `failure_reason`, `feedback_rating`, `feedback_status`, `location_status`, `login_event_id`, `login_as`.

Real vs synthetic everywhere: `is_synthetic` (business indices) / `labels.synthetic` (APM).

## Geographic sign-in map (Maps app — 2 minutes)

1. **Analytics → Maps → Create map → Add layer → Documents**.
2. Data view **Tensai · Login events**, geospatial field **`geo_location`**.
3. Layer filter: `event : "login" and location_status : "granted"` (add `and not is_synthetic : true` for real customers only).
4. Optional: **Add layer → Clusters** on the same field for density at low zoom; style by `outcome`.
5. Save, then **Add to dashboard** (e.g. the Journeys dashboard).

Only consented, browser-reported coordinates exist — nothing is derived from IP addresses — so sign-ins with any
other `location_status` are counted on the "Sign-in Location Consent" panel but are never placed on the map.

## SecBank dashboards D0-D9 and the Canvas wallboard

`secbank-dashboards.ndjson`, generated by `build-secbank.mjs` (`node kibana/build-secbank.mjs`), holds 10 dashboards
(`SecBank D0 · Bank Pulse` ... `SecBank D9 · AI Accountability`), the shared navigation links panel, 9 data views and
the 4-page Canvas workpad `SecBank wallboard` (Pulse, Problems, Pulse, Stack: autoplay gives Pulse twice the wall time).
Every id starts with `secbank-` / `workpad-secbank-`, so importing never touches the Tensai dashboards above.

Import: **Stack Management → Saved Objects → Import** (overwrite only matters when re-importing a newer SecBank build).

Data (written by `api/bin/setup-elastic.php`, `simulate.php`, `export-to-elastic.php`, `journey-health.php`):
`logs-bank.business-default`, `logs-bank.app-default`, `logs-bank.synthetics-default`, `metrics-bank.platform-default`,
`bank-journey-health`, `bank-problems`, `bank-problem-rank`, `bank-risks`, `bank-ai-scores`, lookups `bank-branches`,
`bank-journeys`, `bank-journey-steps`, `bank-customers`, and `traces-apm*`. `bank-demo-ledger` (ground truth) is never read
by any panel.

Panels are ES|QL Lens charts (105), Vega-Lite (journey health heatmap, branch bubble chart, query-time box plot, AI
confusion matrix), one Maps panel, saved searches and Markdown. The Canvas uses Elasticsearch SQL (50 queries). Check every
query against a cluster that has data:

    node kibana/build-secbank.mjs --check https://<es-endpoint> --to=<epoch end of window>   # ES_BANK_API_KEY in the env

`SECBANK_CANVAS_TIME="2026-11-01T16:46:00Z,2026-11-01T17:46:00Z" node kibana/build-secbank.mjs` pins the Canvas time
filter (frozen demo); the default is the last 60 minutes. D3 defaults to 24 hours, D9 to 30 days, the rest to 60 minutes.

Where the spec names a Kibana object that must exist first (SLOs, alert rules, ML jobs, Synthetics monitors, Cases,
Workflows, Agent Builder), the panel uses the spec's fallback on our indices: SLO burn rates from `bank-journey-health`,
problems from the detector (`bank-problems`) instead of alert/case documents, synthetic runs from
`logs-bank.synthetics-default`, change points with ES|QL `CHANGE_POINT`, and links to the APM service map, correlations
and Workflows apps.
